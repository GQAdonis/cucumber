transitions. Current phase46 is unbound.

   on foundation/rust-bdd-sdk. All prior source/evidence retained.
2. Proposed phase46: common safe Rust source/evidence SDK, actual Node/Python FFI,
   private local archives, errors/identity fidelity, Rust extension interface.
3. Native runtime extension: captured dynamic registry using existing matcher,
   per-run World factory, owned source metadata, typed foreign outcomes and
   independent-run coordination. Preserve legacy APIs and native scheduling.

   fresh Worlds, failures/hooks/attachments/retries and cancellation/late-result

   with ten scenarios/64 steps passed in the completed separate docs boundary;
   README and curated guides; preserve mdBook and existing workflows. Clearly
   label GQAdonis forks; use researched official greens/Lato as visual reference
   with applicable attribution. No assumed logo trademark permission/endorsement.
   Hosting undecided; no deployer or CNAME.
6. Package preparation: decide owned names/module names, runtime/platform matrix,
   archive dependency closure, versions/licenses and credential ownership/access.
   No secret values in records. No registry registration/publication until resolved.
   Avoid v* tags that trigger existing Rust publication.
7. Independent audit/corrections: after implementation and BDD, review both repos
   and all core/SDK/FFI/wrapper/docs/package surfaces. Retain findings/dispositions;
   behavioral repairs retain phase-boundary rules. No needless churn or clean
   claim before required corrections and review.
8. Upstream: only after completion/review, inspect current policies/existing issues,
   split reviewable contributions, create authorized matching issues/PRs. Parser
   precedes dependent core. Fork-specific sites/adapters remain separate if not
   suitable upstream. No premature issues/PRs.
